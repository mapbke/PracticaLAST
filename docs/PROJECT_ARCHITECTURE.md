# Архитектура Kurotsuki

`create_app()` загружает конфигурацию, подключает CSRF, регистрирует два blueprint, создаёт SQLite-таблицу при отсутствии и закрывает соединение после запроса. `run.py` и `run_https.py` используют одну фабрику; HTTPS-режим меняет cookie и URL, не бизнес-логику.

`routes.py` рендерит Jinja-шаблоны и возвращает robots/sitemap. `catalog.py` содержит демонстрационный контент и конфигурации карточек. Карточки услуг и продуктов получают цены через `pricing.calculate`. `pricing.py` содержит все тарифы, проверку типов и сборку нормализованного результата. `api.py` обрабатывает JSON и заявку; `database.py` управляет соединением SQLite; `security.py` задаёт CSRF и HTTP-политику.

## Поток расчёта

1. Событие формы вызывает `readConfig()`.
2. Состояние `state.configurator` меняется, цена временно недоступна.
3. `fetch('/api/calculate')` отправляет JSON и CSRF-токен.
4. Flask проверяет параметры и считает integer RUB.
5. Только актуальная версия ответа записывается в `state.quote`.
6. `renderPrice()` и summary меняют DOM без перезагрузки.

## Корзина

`state.cart` хранит серверные quote-объекты. В localStorage сохраняются только конфигурации. При восстановлении `Promise.allSettled` позволяет выявить отдельные неудачные запросы. Если хотя бы одна позиция не восстановилась, запись в хранилище и изменения блокируются до повторной проверки, чтобы не уничтожить исходную подборку. Тема хранится отдельной операцией.

`cartBusy` исключает одновременные изменения. Количество пересчитывается после паузы ввода 300 ms либо окончания редактирования; невалидное значение возвращает последнюю проверенную позицию. DOM строится через `createElement`, `append`, `replaceChildren` и `textContent`.

## SQLite и заявка

Таблица `leads`: `id`, `created_at`, `name`, `contact`, `car_model`, `message`, `configuration`, `cart`, `total`. Configuration и cart — JSON-текст с серверной нормализацией; total — integer RUB. INSERT выполняется только после полной проверки всех позиций. Ошибка любой позиции не создаёт частичную заявку.

## Темы и адаптивность

CSS custom properties определяют базовые цвета. `theme.js` восстанавливает `data-theme` до загрузки CSS; `main.js` меняет его интерактивно. Светлая тема — намеренный default. Grid/flex и media queries перестраивают карточки, меню и формы. Для узкого экрана уменьшаются заголовки и шапка. `prefers-reduced-motion` учитывается в CSS и программной прокрутке.

## Граница ответственности

Браузер отвечает за взаимодействие и предварительный показ. Сервер отвечает за допустимость данных и сумму. SQLite — локальное хранение. Внешних платёжных, почтовых, Telegram API, фоновых очередей и личного кабинета нет.
