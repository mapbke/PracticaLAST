# Материалы отчёта по ПМ.09

Климов Никита Александрович, 25ИС2-4, 09.02.07. Вариант №5: одностраничный электронный магазин интерьерного тюнинга автомобилей. Название — Kurotsuki.

## 1. Создание одностраничного веб-сайта

Разработан лендинг-витрина на Flask и Jinja2. Главная страница содержит услуги, популярные решения, конфигуратор, материалы, концепты, этапы работы, FAQ и заявку. Якорная навигация позволяет перемещаться по одной странице. Автомобильные кейсы обозначены как демонстрационные. Реальные платежи не выполняются.

## 2. Клиентская часть

Интерфейс реализован на семантическом HTML5, CSS3 и Vanilla JavaScript. Grid и flex формируют адаптивные сетки; CSS-переменные позволяют переключать светлую и тёмную темы. Кнопки, подписи полей, focus-visible, управляемые с клавиатуры диалоги и aria-expanded обеспечивают базовую доступность. Изображения хранятся локально в формате WebP.

## 3. Реактивный интерфейс

Реактивность реализована без React/Vue: обработчики событий изменяют state, после чего функции render обновляют конкретные DOM-узлы. Выбор материала меняет цену, добавление конфигурации меняет счётчик и содержимое корзины, отправка заявки показывает статус. Полная перезагрузка страницы для этих операций не требуется.

## 4. Управление состоянием

Единое состояние включает тему, конфигурацию, quote, корзину и скрытый режим. Серверные цены не сохраняются как доверенные значения. При повторном открытии конфигурации загружаются из localStorage и проверяются API. Во время проверки корзины изменения блокируются. Смена темы не затрагивает хранимую подборку.

## 5. Асинхронное программирование и DOM

`api()` использует fetch, async/await, try/catch и AbortController с таймаутом 15 секунд. Проверяется не только получение ответа, но и HTTP-статус, поскольку fetch сам по себе не отклоняет Promise на любой HTTP-ошибке. [MDN: Using Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch).

Версия `quoteVersion` отбрасывает ответ предыдущего расчёта, если пользователь уже изменил параметры. Восстановление корзины использует `Promise.allSettled` для отдельных запросов. Пользовательский текст помещается через `textContent`.

## 6. Техническая оптимизация

Реализованы title, description, canonical, OpenGraph, favicon, robots.txt, sitemap.xml, 404 и health. Изображения вне первого экрана загружаются лениво. Все изображения вместе занимают около 684 KiB. Main.js подключён через defer, тема восстанавливается до CSS. Проверены пять размеров viewport от 320 до 1440 px: горизонтального переполнения нет.

Локальная демонстрация HTTPS использует самоподписанный сертификат и отдельный порт 5443. Работа сервера и calculate проверена клиентом с явным доверием конкретному сертификату. Production-развёртывание не является результатом локального теста.

## 7. Аудит безопасности

На backend проверяются типы, допустимые значения и ограничения. Цена формируется только сервером; итог заявки пересчитывается независимо от браузера. SQL-запросы параметризованы, CSRFProtect включён, CSP ограничивает внешние ресурсы и выполнение скриптов. При проверке обнаружен и устранён приём номера телефона из одних разделителей. Подробности находятся в SECURITY_AUDIT.md.

## 8. Фрагменты кода и контрольные примеры

Источник тарифов — `app/pricing.py`. Для купе, руля и кожи: `28000 × 110 / 100 = 30800`. Для Alcantara и метки: `(28000 + 9000) × 110 / 100 + 2500 = 43200`. Две единицы дают `86400`.

```python
items = [calculate(item) for item in cart]
total = sum(item['total'] for item in items) if items else config['total']
```

Этот фрагмент API демонстрирует повторный расчёт при сохранении. Пустая корзина использует текущую конфигурацию, непустая — сумму позиций без двойного учёта.

```javascript
const version = ++quoteVersion;
// После асинхронного ответа:
if (version !== quoteVersion) return;
```

Так интерфейс защищается от перестановки асинхронных ответов. Это выдержка принципа; полный код расположен в `app/static/js/main.js`.

## 9. Проверки и иллюстрации отчёта

Проходят 53 pytest и 8 Node-тестов. В браузере проверены форма, корзина, темы, FAQ, скрытый пресет и адаптивность. Полные снимки находятся в `docs/screenshots`, перечень отдельных кадров — в SCREENSHOTS.md. Точный протокол с границами проверки — в TESTING.md.
