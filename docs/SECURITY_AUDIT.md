# Аудит безопасности

Объект: собственное локальное приложение Kurotsuki. Дата проверки: 16.09.2026. Сторонние сайты не тестировались.

## XSS

Jinja использует autoescape. Пользовательские строки не попадают в `innerHTML` или `|safe`. Клиент создаёт узлы и присваивает `textContent`. Сохранённые заявки не публикуются через GET-маршруты. Строка `<script>alert(1)</script>` была передана в комментарии: она сохранена буквально, исполнения не наблюдалось. Если позже появится кабинет заявок, его вывод также обязан экранировать строки.

## SQL Injection

INSERT использует placeholders `?` и отдельный tuple значений. Комментарий с `'; DROP TABLE leads;--` не изменяет структуру SQL. Автотест подтвердил сохранность таблицы и буквального текста. Подход соответствует [рекомендациям OWASP о параметризованных запросах](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html).

## CSRF

Flask-WTF защищает оба POST. Токен расположен в meta-теге, передаётся в `X-CSRFToken` вместе с cookie. Отсутствующий/неверный токен возвращает 400. На HTTPS библиотека проверяет Referer. При устаревшей сессии интерфейс просит обновить страницу. [Документация Flask-WTF](https://flask-wtf.readthedocs.io/en/1.2.x/csrf/).

## Валидация

JSON должен быть объектом. Кузов, объект, материал и строчка проверяются по спискам допустимых значений. Quantity — именно int 1–20, bool не принимается. Опции — именно bool. Корзина ограничена 30 конфигурациями. Неизвестные IDs без корректной конфигурации отклоняются.

Имя: 2–80 символов, контакт: 5–100 до отдельной проверки формата, автомобиль: 2–120, комментарий: до 2000. Контрольные символы ограничены, края строк обрезаются. Телефон обязан содержать 7–15 цифр: обнаруженная возможность передать одни дефисы исправлена. Telegram проверяется как формат строки, существование аккаунта не устанавливается.

Общий размер тела — 65536 байт. Проверены пустые, слишком длинные значения, null/массив вместо объекта, отрицательное, дробное и слишком большое количество. HTML из комментария не «очищается» разрушительным удалением символов: он хранится как данные, а безопасность обеспечивается способом использования и вывода.

## Подмена стоимости

`pricing.calculate` самостоятельно формирует возвращаемую конфигурацию и цену. При заявке рассчитывает каждую позицию повторно. Переданные `total=1`, `price=1` не принимаются. Цена в localStorage не является основанием для записи итоговой суммы. При восстановлении браузер получает свежие серверные оценки.

## Заголовки, HTTPS, секреты

CSP разрешает только локальные ресурсы, запрещает inline-скрипты и встраивание во фреймы. Дополнительно установлены X-Frame-Options=DENY, nosniff, Referrer-Policy и Permissions-Policy. Главная/API не кэшируются. Cookie: HttpOnly, SameSite=Lax, Secure для HTTPS. HSTS выдаётся по HTTPS.

FORCE_HTTPS перенаправляет на настроенный PUBLIC_URL, а не на произвольный Host. Неверная HTTP-конфигурация при FORCE_HTTPS отклоняется при старте. Redirect выполняется до CSRF на HTTP; HTTPS POST по-прежнему защищён.

SECRET_KEY берётся из окружения. Случайный ключ при отсутствии переменной допустим для одного процесса разработки; постоянная конфигурация необходима для внешнего размещения. `.env`, SQLite, `.venv`, private key и сертификаты исключены из Git.

## Остаточные ограничения

Нет rate limiting, CAPTCHA, административной аутентификации, шифрования БД на диске и политики автоматического удаления заявок. Публичных маршрутов чтения заявок также нет. Для реального размещения нужны отдельная эксплуатационная конфигурация, резервное копирование, ограничение запросов, контроль доступа и правила хранения контактов. Успешные тесты не являются доказательством отсутствия всех уязвимостей.

Итог локальной проверки: исправлена валидация телефона и порядок HTTPS redirect; 53 серверных и 8 клиентских регрессионных тестов проходят.
