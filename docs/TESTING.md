# Проверка Kurotsuki

Дата: 16.09.2026. Проверена существующая версия проекта с точечными исправлениями, без пересборки с нуля.

## Автоматические проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --test tests/frontend.test.cjs
node --check app/static/js/main.js
.\.venv\Scripts\python.exe -m pip check
```

Результат: **53/53 pytest**, **8/8 Node**, синтаксических ошибок JS нет, `pip check`: `No broken requirements found`.

Pytest использует временную SQLite на каждый тест. CSRF не отключается: тест получает настоящий токен со страницы и сохраняет сессионную cookie.

| Область | Что проверяется |
| --- | --- |
| Маршруты | Главная, robots, sitemap, health, 404, все локальные ссылки на static |
| Расчёт | Контрольная цена, опции, количество, строгие типы, неизвестные значения |
| Подмена цены | `price`, `unitPrice`, `total` не меняют серверный результат |
| Заявки | Валидация, запись, повторный расчёт корзины, отсутствие записи при ошибке |
| Безопасность | Нет/неверный CSRF, SQL/XSS-подобный текст, лимит тела 64 KiB, заголовки |
| Контакт | Дефисы без цифр, короткие/длинные номера, некорректные Telegram; допустимые форматы |
| HTTPS | 308 до проверки CSRF на HTTP, CSRF на HTTPS, отказ при неверном PUBLIC_URL |

Node-тесты исполняют реальные функции `main.js` в изолированной среде с заменой DOM-рендера и сетевого ответа. Они проверяют сохранность корзины при смене темы, частичный сбой восстановления и повторную попытку, запоздавшие ответы расчёта, отказ при неправильном количестве, гонку добавлений у лимита 30 позиций, сетевую ошибку и не-JSON ответ. Это проверки логики, а не замена браузерной проверки.

## Проверка в браузере

Использован встроенный Chromium-браузер. Тестовые контакты не отправлялись внешним сервисам.

| Сценарий | Наблюдаемый результат |
| --- | --- |
| Базовая конфигурация | Купе / руль / кожа = 30 800 ₽ |
| Alcantara + центральная метка | 43 200 ₽ за единицу |
| Ввод количества 2 в корзине | После короткой паузы 86 400 ₽, без необходимости покидать поле |
| Количество 0 | Ошибка, возврат к допустимым 2 единицам и 86 400 ₽ |
| Тема + перезагрузка | Тема восстановилась, корзина сохранила 2 единицы |
| Второй товар | Глянцевый карбон + метка + перфорация, 2 шт. = 123 000 ₽; общий итог 209 400 ₽ |
| Удаление второй позиции | Итог вернулся к 86 400 ₽ |
| Неверный контакт `-------` | После исправления сервер возвращает ошибку, форма сохраняет введённые поля |
| Успешная заявка | Получен ID №2 и сумма 86 400 ₽; запись подтверждена чтением SQLite |
| SQL/XSS-подобный комментарий | Сохранён как строка, код не выполнялся, таблица осталась доступной |
| FAQ | Открытие ответа и изменение aria-expanded без перезагрузки |
| Мобильное меню | Открывается, переход по якорю закрывает меню |
| Пасхалка | Три клика открывают диалог; Psychopathic применяет Alcantara, красную строчку, метку и перфорацию |
| Ресурсы | Все 25 img-элементов загрузились, битых якорей нет |
| Консоль финальной страницы | Ошибок и предупреждений JavaScript не обнаружено |

До исправления валидации была сохранена тестовая заявка №1 с некорректным контактом. Она остаётся локальным QA-следом и не включается в Git.

## HTTPS smoke test

Запущен `run_https.py`. Клиент Python использовал `ssl.create_default_context(cafile='certs/dev-cert.pem')`, то есть проверял конкретный dev-сертификат и имя хоста. Получены: главная `200`, calculate `200` и `30800`, robots/sitemap `200`; присутствует HSTS. Проверка сертификатов не отключалась, настройки доверия браузера и ОС не менялись.
